# Yazhal development and feature guide

Project: https://github.com/Kausthuban/Yazhal

## Feature controls

| Feature | Location / behavior |
| --- | --- |
| Offline metadata and artwork | Settings → Local music & downloads → Metadata. Enable lookup, select a song, adjust artist/title, review matches and apply. Missing art does not prevent confirmed metadata edits. Original audio bytes/tags stay untouched. |
| Offline suggestions | Home → From your offline library. Library artists/albums, real file-play starts, frequency and recency influence suggestions. Learning can be disabled and history cleared in Metadata settings. |
| Online personalization | Requires the existing external-recommendations setting. Uses up to three descriptive artist/title searches with a 15-minute cache; no audio, source paths or full history are uploaded. |
| FLAC sources | Settings → FLAC sources & extensions. Sources start disabled. Search's FLAC action opens the separate catalog. The built-in provider covers Live Music Archive recordings; other sources need compatible manifests. |
| Download destination | Settings → Download location. Select a writable folder using the system picker or restore app-private storage. Applies to future downloads. |
| Multiple music folders | Local music → Folders. Add folders, scan manually, review status/errors and toggle each automatic scan selection. |
| Automatic scanning | Disabled initially. Checks on startup/resume and every 15 minutes while foregrounded; successful scans are throttled to a 15-minute minimum. This is not a background/killed-app service. Missing files and folder removal do not delete originals. Edited imported playlists are retained. |
| Bulk actions / scrolling | Select tracks on song pages for playlist/queue actions. Use the interactive vertical thumb to navigate long lists. |
| Credits | About links the Yazhal repository and separately credits the original project and author. |

Offline listening history counts a matching file source once when actual playback
starts. Preparing, buffering and pause/resume events do not create extra plays;
explicit replay can count again. History is device-local and bounded to 1,000 songs.

Metadata lookup sends artist/title text to MusicBrainz. Cover Art Archive supplies
available release artwork. Confirmed metadata and cached covers live in the app's
registry/private directory. New/custom UI labels currently use English.

FLAC catalogs are declarative JSON and cannot run scripts. URL hosts, redirects,
response sizes and FLAC file signatures are checked. There is no transcoding or
compressed-to-lossless renaming. Downloaded files remain playable when a source
is disabled; a stream already playing is not forcibly stopped. See EXTENSIONS.md.

## Building and updating

The README lists the pinned toolchain and commands. Localization/plugin files and
Android wrapper launchers are regenerated by Flutter as needed. Keep the root
pubspec.lock committed. Vendored packages under `packages/` are required by the
path dependencies and must stay in the repository with their licenses.

When changing the version, update `pubspec.yaml` and `lib/constants/version.dart`;
`update.sh` can synchronize the numeric Dart version from pubspec.yaml.
Use a consistent signing key for future updates. Release signing/release publishing
is not configured by this source package. Do not commit key.properties or keystores.

After installing under the new application identity, restore a previous backup,
reselect folders to grant access, and pair devices using Yazhal on both sides.
Old app-private downloads and old sharing protocols do not migrate automatically.
